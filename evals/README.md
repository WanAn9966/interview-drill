# 面试评测样本规范（v1）

`seeds.json` 是 D03 自编的虚构样本，只用于开发集。它们不来自用户简历或真实面试，也未经过人工标注；所有 `review.status` 均为 `pending`。运行 `python scripts/validate_evals.py` 检查结构、来源声明、引用链和粗粒度个人信息模式。

## 一条样本的业务链

`role` 与 `jd` 指明目标岗位。`resume_cards` 按项目、实习、工作经历、学历、工作技能分卡；卡片文字是待核验主张，不等于已证实的履历。`question` 必须是面试官向求职者发问，并以 `jd_quote` 和 `resume_card_id` / `resume_quote` 分别锚定 JD 和简历原文。`answer` 属于求职者；`feedback_target.answer_quote` 必须是回答中的连续原文，`gap` 与 `action` 仅是撰写者的参考方向，不能冒充模型实测输出或人工金标。

`case_id` 全局唯一，`group_id` 表示同一简历/JD 来源组。一个组只能位于 `dev` 或 `holdout` 一侧；冻结集建立后按组分割，避免同一人的改写案例同时进入开发与验收集。`schema_version` 当前固定为 1。`role_family` 是覆盖统计用的开放文本，不能成为仅支持固定岗位的产品限制。首批样本包括 AI/软件工程、产品、数据分析、客户服务、设计五类岗位族。

## 来源与授权

`source.type=synthetic` 且 `authorization_ref=self-authored` 表示项目自编的虚构样本。将来使用真实经历时，先取得可核验的使用授权并完成脱敏，再设为 `authorized_deidentified`，`authorization_ref` 写内部授权记录 ID，不能写姓名、联系方式或授权书正文。原始简历、音频、面试记录和授权文件不要放进 Git。校验器仅拦截明显邮箱、手机号和密钥形态；它不能证明已经完成充分脱敏或真实授权。真实样本入库前仍须由负责人复核，尤其检查公司/学校/项目组合造成的间接识别风险。

## 人工标注口径

审核者应逐条读 JD、经历卡、问题、回答和反馈。`review.status=reviewed` 时必须填写匿名 `reviewer_id`、ISO 日期 `reviewed_on`、下列五项 0–2 分整数标签。0 为不满足，1 为部分满足或证据不足，2 为满足；存在争议时保留两位审核者的原始标注记录并记录分歧，最终共识才写入样本。禁止把未审样本或 AI 自评分记为人工标签。

| 标签 | 2 分判据 | 0 分典型情况 |
| --- | --- | --- |
| `role_fit` | 问题对应 JD 要求且适合该岗位 | 仅套用其他岗位题库 |
| `question_grounding` | 问题准确引用 JD 与简历，面试官不代答 | 引用不存在的经历或错认身份 |
| `answer_evidence` | 回答明确本人动作、依据及可核验结果/边界 | 空泛结论或无法支撑的数字 |
| `feedback_grounding` | 反馈引用真实回答，指出有据可查的缺口 | 虚构原话、结果或未问过的内容 |
| `actionability` | 改进动作具体，可在下次回答中执行 | 只有“继续努力”等泛泛建议 |

## 迭代用法

当前 7 条只用于验证数据格式与业务断言，不能统计模型质量。D34 需要另行收集至少 100 条**获授权、脱敏、人工审核**的样本，覆盖至少四类岗位，冻结 `holdout`，按 `group_id` 分割并记录审核分歧。届时模型输出需与样本目标及人工标签比较；要同时报告每类岗位的样本量、错误例子和版本号，不能把格式校验通过率当成面试质量。
