# 深问 · 本地 AI 面试工作台

基于简历与任意目标岗位 JD 的个人面试练习原型，不限技术岗位。可上传简历、确认经历片段、分析岗位要求、动态追问、语音回答、朗读问题和总结，最后导出面试记录与复盘。三个技术岗位按钮仅为名称快捷填入。

## 启动

需要 Python 3.11 或以上；无需前端构建工具。

```powershell
python -m pip install -r requirements.txt
if (!(Test-Path .env)) { Copy-Item .env.example .env }
python -m uvicorn app:app --host 127.0.0.1 --port 8765
```

浏览器访问 <http://127.0.0.1:8765>。Windows 也可运行 `start.ps1`。建议用当前 Chrome 或 Edge。首次使用需授权麦克风。

## 模型配置

默认接入阿里云百炼华北2（北京）。编辑 `.env`，只需填写本地密钥：

```dotenv
AI_PROVIDER=bailian
BAILIAN_REGION=beijing
DASHSCOPE_API_KEY=在本机填写你的新密钥
```

默认使用 `qwen-plus` 做岗位分析、追问与复盘，`qwen3-asr-flash` 识别回答，`qwen3-tts-flash`（Cherry 音色）朗读。三项服务共用密钥，但实际能否调用取决于该业务空间的模型权限和账户额度。地区必须与密钥一致；新加坡填写 `singapore`。北京默认使用官方仍支持的 `dashscope.aliyuncs.com` 域名；也可通过下方 URL 参数覆盖为控制台的业务空间专属完整接口地址。

不要把真实密钥写进前端或提交 Git。修改后重启服务、刷新网页。页面“已配置”仅说明参数齐全，不代表真实 API 验证通过。轮流语音问答需要联网；不必部署云服务器或开通 OSS。

百炼识别使用 Base64 音频消息；浏览器录制 WebM/OGG，单次最多3分钟、10MB。合成文本超过600字时按句分段请求，下载 WAV 并合并后播放，不截掉后续总结。此版本不是实时打断式语音，长总结需等待分段合成。协议参考：[识别](https://help.aliyun.com/zh/model-studio/qwen-asr-api-reference)、[合成](https://help.aliyun.com/zh/model-studio/qwen-tts-api)。

切换其他兼容供应商：设置 `AI_PROVIDER=generic`，再填写 `LLM_URL`（完整 chat/completions 地址）、`LLM_KEY`、`LLM_MODEL` 及需要的语音配置。百炼模式也可用这些变量覆盖默认地址、密钥和模型，空值则使用默认值。

- 未配置模型仍可选择“规则演示”，检查页面和面试流程。其追问来自规则，报告不包含能力评分，不等同 AI 深挖。
- 联网模式会发送确认后的经历、JD、必要对话给所配置的模型。云端数据留存受供应商政策约束。
- 语音识别可设置 `STT_URL/STT_KEY/STT_MODEL`，要求接口支持 multipart 的 file/model/language 参数和 JSON text 返回值。
- 语音合成可设置 `TTS_URL/TTS_KEY/TTS_MODEL/TTS_VOICE`，要求接口支持 model/input/voice/response_format 参数及 MP3 音频返回值。
- 上述 multipart/MP3 格式用于 generic 模式；百炼模式使用独立适配。其他供应商协议需单独核对。当前仍需用有效账户做真实 API 联调。
- 没有 STT 配置时尝试浏览器语音识别，可能依赖浏览器云服务，兼容性与网络可用性有限。
- 没有 TTS 配置时使用系统中文音色。没有中文音色则提示安装系统中文语音包或配置 TTS。

## 使用

1. 上传 PDF/DOCX/TXT/MD，或粘贴简历；扫描 PDF 暂不支持 OCR。
2. 系统按章节整理为项目、实习经历、学历、工作技能；正式工作经历单列，无法判断的内容保留在其他区。支持中英文标题、项目日期分段、Word段落/表格顺序、常见双栏PDF。核对后统一确认，可编辑、补充或移动条目。解析在本机执行，无需API。
3. 填写任意目标岗位名称（快速模板仅是预设方向，可留空），粘贴可选 JD，再选风格和时长。联网模式会把岗位、JD 和确认后的经历交给模型；有 JD 时追问会引用岗位要求原文。
4. 面试官提问后录音，停止后核对转写文本，再提交。也可直接打字。可以暂停、继续、重播或结束。
5. 结束时自动尝试生成复盘并朗读总结；失败后可重试。导出 Markdown 或 JSON，历史页可重新打开会话。

## 当前边界

- 已实现轮流语音问答；尚未实现流式字幕、自动接话和自然打断。
- 面试开场固定由面试官邀请求职者自我介绍；后续问答按 assistant=面试官、user=求职者传入模型。模型返回的问题经过角色字段和常见代答表达检查，失败重试一次，再使用当前阶段的规则问题；这项检查不能保证识别所有语义上的角色错位。复盘使用独立提示词。
- 追问次数由阶段上限控制；联网模型生成具体追问，尚未自动判断“信息已充分”而提前跳过。
- 支持本地会话恢复，但没有保存未提交文本。关闭浏览器前请提交回答或自行复制。
- 简历源文件只在解析请求内读取；会话保存确认的片段，不保存原文件。
- 云端录音在页面内临时保存，可下载和重试识别；刷新后不保留，浏览器识别模式不保留原始音频。
- 原型评分为回答训练等级 1-5；详细六维评分、跨场趋势、HTML/PDF 报告和离线模型属于后续计划。
- 时长到点后，下一次提交回答时结束，不会截断正在说的内容。暂停不计时；浏览器关闭而未暂停时继续计时。
- 报告检查引用是否存在于原始回答；这能防止虚构引语，不能保证所有评价都正确。报告仍需人工复核。

## 简历解析 v2

旧逻辑只选择8行关键词片段，会丢掉短标题、学校名称和后续经历。新逻辑见 `resume_parser.py`：提取全文 → 识别章节标题 → 按项目/日期整理条目 → 分类与来源提示 → 用户确认 → 面试上下文。

- 分类结果始终展示项目、实习经历、学历、工作技能四区；没有内容显示“未识别到”，不编造经历。
- 长内容分段保留，不再截取前8行或前1800字；简历总量上限60000字，超过时明确拒绝而非静默截断。
- DOCX按正文顺序遍历段落、表格与嵌套表格，合并单元格不重复提取；识别到文本框时追加并提示核对位置。
- PDF使用布局文本，对有明显栏间空隙且两侧均有章节标题的双栏进行拆分；混合排版、无标准标题和扫描件仍需人工核对或先OCR，不能保证所有模板自动识别。
- 本版本采用本地规则结构解析，不宣称已实现通用的AI语义理解或OCR。分类是对用户原文的整理，不是履历真实性认证。
- 学历与技能作为独立背景传给AI，不再用来生成“项目深挖”；只有学历时可练习学习与实践问题。
- 页面顶部显示API配置状态。缺少LLM配置时仅允许规则演示；简历解析成功并不代表真实AI服务已接入。

方法参考：[Unstructured按文档结构分块](https://docs.unstructured.io/api-reference/legacy-api/partition/chunking)、[python-docx按正文顺序遍历内容](https://python-docx.readthedocs.io/en/latest/api/document.html)、[PyMuPDF关于PDF阅读顺序的说明](https://pymupdf.readthedocs.io/en/latest/recipes-text.html)。实现没有复制这些项目代码，也没有引入其云端服务。
